# BUG 日志、当前代码预分析与 AI 协议自适应设计

日期：2026-10-21。状态：待用户评审，尚未实施。

## 需求与现状

用户要求：检测或刷新问题后先下载对应日志；BUG AI 预分析使用当前代码，不自动更新远端；模型 API 地址和 AI 代理地址均允许只输入去掉协议后的内容，优先 HTTPS，HTTPS 不可用时使用 HTTP。

核对当前 0.7.6：Jira 适配器只保存附件 ID、文件名、类型、大小，未下载；Trinity 详情明确声明附件尚未接入；BUG 任务与其他上下文任务共用 synchronize，执行远端更新；模型 API 和代理均要求完整 URL，无统一协议选择阶段。

本次属于跨模块行为调整。复用已有来源连接、任务队列、内容快照存储和项目关联，避免建立第二套问题或 AI 配置。

## 一、问题日志材料

### 获取流程

问题读取并验证实例、项目、负责人后，发现其平台附件及经验证的日志资源。新增或附件版本变化时安排下载；重复刷新命中已完成的同一附件版本，不重复下载。账号级 Trinity 问题在多个代码项目展示时共享同份材料。

先对当前真实 Jira CLI 和 Trinity 实例核对附件列表、下载认证及重定向契约，再实现适配器与脱敏回归样例，不编造 Trinity 接口或将“接口尚不支持”当成没有附件。Jira CLI 继续使用其本机登录能力，Trinity 继续使用已有加密会话，不要求用户重复配置下载密码。

下载不依赖 AI，也不更新代码。问题列表读取与下载状态分开记录：附件失败不会隐藏成功读取的问题，但必须明确显示失败原因。

附件版本以平台标识、实例、问题 ID、附件 ID 及版本信息识别；完成后计算内容哈希。同一 ID 内容变化产生新的材料版本。临时文件写完并校验后才发布为可用材料，不把中断文件标为已下载。

### 展示和分析

问题卡片显示：无日志、等待下载、下载中、已下载、下载失败，以及数量、大小、材料版本；提供重试和打开本地材料入口。确认“无日志”与无法读取附件列表必须区分。

BUG 预分析前等待本问题当前日志准备完成，再将日志索引和按需读取工具交给 AI。日志未准备好时显示原因和重试入口；用户可明确选择“仅按代码和问题描述分析”，报告必须记录本次未使用日志，不做静默降级。平台已确认没有日志时允许分析，并记录材料缺口。

优先解析文本日志和 ZIP 日志包。保留原始文件、来源与哈希；大日志分块索引和读取，报告注明实际读取的文件及行范围。未支持格式保留原件并明确显示未解析，不宣称 AI 已读。只下载文件不算完成日志分析接入。

默认预算：单附件 512 MiB、单问题下载总计 2 GiB、并行下载最多 2 个；解包总计 2 GiB、最多 10000 个文件、最多嵌套 2 层。超限明确报错，不能悄悄截成完整日志。文本索引覆盖范围和截断情况必须在材料与报告中可见。

只使用已验证的平台附件和日志下载机制。描述或评论中的普通 URL 不自动当作可携带平台凭据的下载地址；外部网盘或独立认证资源明确显示待适配。不得把平台 token 发送给任意附件重定向主机。验证目标地址、文件名、路径、类型及大小；解包禁止路径穿越、符号链接与自动执行。

## 二、BUG 预分析使用当前代码

BUG 任务改为：重新读取问题及归属 → 准备日志 → 捕获当前工作区代码快照 → 索引 → AI 分析 → 校验保存。

BUG 分析不执行 fetch、pull、rebase、切换分支或 stash。界面按钮改为“基于当前代码预分析”。项目管理“更新代码”仍是用户主动触发的独立 Git 操作；需求核对既有同步行为不在本次擅自更改。

“当前代码”包括当前目录已跟踪文件的未提交修改、暂存修改、新增文件与删除结果。未跟踪文件经过既有路径与敏感文件规则过滤后纳入；.git、凭据、敏感文件、符号链接和构建产物不作为分析材料。

分析记录实际分支、HEAD、文件清单及工作区内容哈希；配置的更新分支不再强制决定 BUG 分析读哪个分支。工作区文件保存为不可变内容快照，代码工具、检索与证据校验共用快照读取入口；不得仅记录 HEAD 后仍从 HEAD 读取，从而漏掉未提交代码。

捕获期间检测文件变化，不能拼接多个时刻的混合材料；变化时明确重试或报错。分析期间工作区再次改变时要求重新分析，不把旧结果当成当前工作区结论。报告清楚标记“当前工作区快照”，有未提交修改时不能把它标为等同某个 Git 提交。

继续保留独立分析目录配置。开发者希望分析自己尚未提交的代码时，可把这些代码放在所配置目录中；本次不自动切回此前有改动的原开发目录。

## 三、模型 API 与代理的协议自适应

每个 AI 连接仍只有一份配置。API 服务和可选代理分别接受 host[:port][/path]，也兼容粘贴完整 URL；界面展示同一地址派生的 HTTPS、HTTP 两个候选，不要求建立两条 AI 连接。

统一地址解析与协议选择，API、HTTP 代理和订阅 CLI 代理共用规则：

1. 拒绝 URL 内嵌账号密码、查询和片段，保留 API 路径前缀；代理地址不接受业务路径。
2. 发模型材料前先探测地址协议；代理先确定其协议，再经此代理确定模型 API 协议。优先 HTTPS，连接或协议不可用时探测 HTTP。
3. 选择成功后才发实际模型请求，不因协议尝试重复提交同一份推理请求，避免重复调用和计费。
4. HTTP 401、403、429、模型不存在或服务返回的业务错误不属于协议不可用，不触发 HTTP 切换。
5. 订阅工具只自适应用户配置的代理，不改写 Codex/Claude 自己管理的服务地址、账号或认证流程。CLI 启动前确定代理协议，通过环境传入。
6. 界面及任务历史显示最终使用协议和 HTTPS 失败的简要原因；HTTP 连接明确标明未加密，不能隐藏切换。错误输出不包含密钥、token、完整请求正文或日志内容。
7. 两个候选都不可用时明确失败。缓存协议选择只用于同一地址和配置版本，重新测试、编辑或连接失效时重新探测；它不是另一套连接配置。

已有完整地址配置在载入时归一化为候选地址，保留连接 ID、默认关系及项目覆盖，不要求用户删除重建连接。Jira、Trinity、日志下载和飞书继续直连；本次协议自适应只影响 AI 服务与 AI 代理。

## 影响范围

- contracts：问题附件/日志材料状态、代码工作区快照、AI 地址配置及诊断结果。
- adapters：Jira/Trinity 附件发现与下载、日志解析、当前工作区捕获、统一 AI 协议探测及订阅工具环境。
- core：问题材料准备、BUG 任务顺序、统一快照取证、分析前后材料版本校验。
- storage：日志内容与来源引用、材料状态、工作区快照；必要的数据库升级须备份并测试。
- desktop：日志进度与重试、当前代码预分析按钮、报告材料范围、AI 地址输入与最终协议展示。

## 验收

1. 刷新真实问题能看见日志发现和下载步骤；重复刷新不重复下载，新增日志会更新材料，下载失败可见并能重试。
2. AI 可检索并读取真实日志片段；报告带来源与读取范围，不只使用问题描述。
3. 有未提交代码时可预分析并实际读到修改；不发生远端更新或分支变化；中途改动能被检测。
4. API 和代理分别验证 HTTPS 成功、HTTPS 不可用而 HTTP 成功、两者失败、认证错误不切换；探测不携带材料和密钥，实际模型请求不被重复发送。
5. 真实复验当前 Trinity 账号、已确认的非网联项目、E0V空调及独立分析目录；联调不改 BUG 状态、负责人或评论，不修改业务代码。
6. 通过目标单测、类型检查/lint、完整单测、打包后的桌面回归，再交付新版本。自动测试使用隔离数据与模拟平台；真实联调结果单独记录。

设计获认可后整理具体实施计划，按用户选定方式执行并重新打包。
