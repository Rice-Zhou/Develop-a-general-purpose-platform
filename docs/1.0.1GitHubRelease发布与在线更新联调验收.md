## 当前网络的直连限制

- api.github.com 可访问，Release 元数据读取、创建和上传均成功。
- github.com:443 直连失败，解析地址为 20.205.243.166；Node/Undici、curl `--noproxy '*'` 和禁用代理的 Git 均失败。
- 客户端按产品要求直连，不使用系统代理，因此 1.0.1 的清单/安装包默认链接在此网络中被 github.com 这一跳阻断。
- 官方附件 API → release-assets.githubusercontent.com 的路径可以直连。使用发布者认证向官方 API 请求附件，再在不转发认证头的条件下直连官方 CDN，实际完整下载了发布的安装包，大小与 SHA-256 均通过。
- 此 API 下载属于发布验收工具，不是对 1.0.1 客户端的隐式替换或代理 fallback；不能据此声称 1.0.1 自动下载已经通过。

结论：当前网络并非所有 GitHub 下载都需要代理；默认浏览器下载入口与官方附件 API 的可达性不同。客户端完整自动更新仍需恢复其现有下载入口的直连网络，或在后续版本中明确设计官方 API 附件读取支持。
