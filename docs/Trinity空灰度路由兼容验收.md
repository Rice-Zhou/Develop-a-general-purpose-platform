# Trinity 空灰度路由兼容验收（0.7.3）

## 已确认的真实原因

2026-10-20，经用户授权以其会话令牌只读请求配置实例的 `/sys/user/userinfo`，返回业务码 200、有效 UID、`apiVersion="Trinity V8.16.0"`、`isGray=null`。0.7.2 强制要求灰度为布尔值，误把正常的空灰度返回判为协议错误。

站点公开前端把灰度返回值原样交给 XMLHttpRequest；其 axios 实现直接调用 `setRequestHeader`，显式 null 作为字符串 `"null"` 发送。携带服务端返回的版本和 `isGray: null` 请求真实列表接口，业务码为 200。未猜测默认 API 版本、未把空值改成 false。

## 修改

- 协议校验接受已证实的布尔型或显式 null 灰度值，统一转换为 HTTP 请求头文本。
- 登录校验与 BUG 适配器继续共用同一个协议解析器及类型，不增加另一套判断。
- 缺失灰度字段仍拒绝；API 版本必须是非空、安全的请求头字符串。拒绝数字、对象、数组、空字符串和换行注入，不新增未经证实的转换。
- 错误只显示固定字段的类型／缺失情况，不输出响应字段值、身份信息或令牌。
- 未修改数据库结构或账号归属校验。

## 验证边界

- 新增 12 项回归测试，覆盖 null、true、false、字段缺失、错误类型及请求头注入；新增 null 场景先复现失败，再修复通过。
- 相关单元测试 49 项通过，5 项依赖原生 Jira CLI 环境的测试跳过。TypeScript 和 ESLint 通过。
- 打包桌面回归 3 项通过：以真实字段形态（V8.16.0／null）验证账号登录保存、身份失败不保存连接、跨项目继承和问题请求头透传；未重新运行完整端到端套件。
- 真实只读验证仅确认 UID、版本和灰度返回形态，以及该路由下身份／列表／单条详情接口的业务响应。没有提交 BUG 修改或发送飞书消息。
- 真实列表返回的问题归属及详情字段仍存在与当前适配器契约的差异（详情缺少旧契约中的 description／updateTime）。完整账号 BUG 列表发布尚未通过真实联调，不将业务码 200 描述为完整读取成功；既有归属校验仍保留。
- 会话令牌仅在临时内存及发往原站点的请求中使用，验证后清理；未写入源码、配置、文档或磁盘响应。
