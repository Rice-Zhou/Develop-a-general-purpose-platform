# 0.3.4 Jira 自动项目选择

## 已确认流程

添加或编辑本地项目时，选择复用 Jira CLI、账号密码登录或已有连接，读取可访问的 Jira 项目及类型名称，搜索并单选一个 Jira 项目。负责人由已验证的登录身份确定。多个代码仓库仍可属于同一本地项目；该本地项目只能绑定一个 Jira 项目。Trinity 原流程保持。

项目 Key、负责人、缺陷类型 ID 不再由用户手填。类型列表允许选择多个类型；唯一明确的 Bug/缺陷/故障类型自动选择，其他情况要求按名称选择。读取失败清楚显示错误，未成功取得新目录前禁止保存 Jira 关联；空项目列表与权限错误分别提示。保存时后台重新读取并验证当前连接、身份、项目和类型。项目草稿 schema 在 IPC 与项目服务的共同边界限制单个 Jira 关联，旧数据不被静默丢弃，编辑旧多范围配置时明确要求重新选择。

## 实现边界

- 项目表单复用原有登录组件，嵌入模式使用普通容器，避免嵌套 HTML form。密码继续通过主进程加密保存；目录查询仅传连接 ID，renderer 不能指定任意请求地址或命令。
- HTTP 读取 `/rest/api/2/myself`、`/project`、`/issuetype`；CLI 使用原生命令读取项目列表及现有 YAML 的命名类型，不改写用户配置。
- CLI 1.7.0 的 `me` 仅返回配置用户名，不能当作服务器认证身份。此版本用 `project IS NOT EMPTY AND assignee = currentUser()` 只读查询一条自己的问题，读取原始详情的规范 assignee，再用 currentUser() 与该 assignee 的交集查询确认身份。仅用于身份确认，不保存样本问题为项目输入，也不自动分析它。
- CLI 列表 raw 投影只有 displayName，不能替代身份 ID；因此身份确认读取原始详情。完全无已分配问题、身份样本格式异常或读取期间发生转交时，明确拒绝绑定并提示账号登录，不回退为配置用户名。当前自动发现仅支持 Server / Data Center；Cloud CLI 缺少可靠 accountId 时拒绝，避免错误负责人范围。
- CLI 原生项目列表 tab 表格严格解析；精确识别 `No projects found.` 的退出码 1 为空列表，其余非零退出保持失败。类型来自本地 CLI 配置，界面明确标注来源及更新要求；HTTP 类型来自服务器可访问类型列表。实际问题导入仍逐条校验项目、负责人和类型。
- 沿用本地直连网络策略；目录读取及保存验证使用 120 秒总预算，CLI 单次命令最多 30 秒，IPC 保留 5 秒回传余量。

## 验证记录

目录适配器和 IPC 新能力均先在缺少实现时失败；新桌面用例先在 0.3.3 确认缺少项目内登录入口。独立审阅发现 CLI 配置身份与真实认证身份可能不同，已用真实 CLI 与本机服务夹具复现配置 bob / 认证 alice 的错误，并加入身份确认、无已分配问题及转交回归。桌面断言发现嵌套 select 文字使精确标签定位失败，改为显式 label/control 关联。编辑时连接晚于项目加载会丢失选择的问题，已由真实桌面用例复现并修复；加载现在等待对应连接。旧多范围配置会要求显式重选，避免自动保留第一项；升级回归在缺少此保护的包中确认失败。

- 全量单测 35 个文件、103 项通过（358.26 秒），包含真实 Jira CLI 1.7.0 与本机服务器的协议验证。TypeScript、ESLint 及安装程序/ZIP 构建通过。
- 完整桌面回归 12 项中 11 项通过；原 desktop 流程在截图步骤出现一次 30 秒超时。最终包定向复验 8 项全部通过（1.6 分钟），覆盖桌面、BUG 预分析、账号/CLI 项目选择、登录与项目引导，包含此前超时的 desktop 用例；原有刷新、删除、需求报告亦已在完整回归通过。
- 账号及真实 CLI 两种项目选择均验证：项目名/Key 搜索、自动身份、单选保存、后台拒绝伪造负责人、编辑保留选择、空项目列表、403 显式失败。账号流程还模拟旧多 Jira 数据视图，验证必须重选一个项目，保存后只剩选定关联。
