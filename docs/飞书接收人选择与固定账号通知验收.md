# 飞书接收人选择与固定账号通知（0.7.5）

## 需求与设计

用户确认：支持输入姓名搜索并选择飞书接收人，保存后通知直接发送给该账号，不再每次检查 CLI 当前用户；授权失效提供重新登录提示并重新打包。

入口为 BUG 工作台的“定时查询与飞书提醒”。保存接收人全局生效，不按代码项目重复配置。仍保留“使用当前 CLI 用户”作为一次性选择入口。未配置接收人时沿用一次当前用户识别，识别成功即保存；后续不再识别。

## 实现

- 通过已核对的 CLI `contact +search-user --query <姓名> --as user --page-size 30 --format json` 搜索，解析 users 中的 open_id、localized_name、department 及 has_more。对应 [官方 v1.0.48 实现](https://github.com/larksuite/cli/blob/v1.0.48/shortcuts/contact/contact_search_user.go)。
- 结果显示姓名、部门和稳定账号 ID，同名账号分别展示，必须明确选择，不自动取第一条。更多结果时提示缩小查询。空结果与失败区分。
- 接收人仅允许从当前搜索结果选择；后端保存自己的候选副本，拒绝伪造的账号选择。搜索结果缓存仅用于选择验证，不是另一个持久化接收人来源。
- 已保存接收人沿用原 monitor state 的 recipient 字段，含可选部门信息；不改数据库 schema。重启后直接使用保存的账号，修改轮询间隔不会覆盖它。
- 发送只调用 `im +messages-send --as bot --user-id <保存的 open_id>`，保留回执检查和持久化幂等键，不再调用当前用户查询。具体指令参见 [官方发送实现](https://github.com/larksuite/cli/blob/v1.0.48/shortcuts/im/im_messages_send.go)。
- 处理 CLI 非零退出及成功退出返回的 authentication 错误：用户授权缺失提示固定的 `lark-cli auth login` 操作；机器人凭据错误单独提示应用配置和发消息权限，避免把机器人问题误当用户登录问题。其他进程错误继续暴露，不吞错或伪造成功。
- 旧的异步当前用户查询不能覆盖新选择。通知发出前检查接收人版本；切换接收人保留待发记录并重新生成其消息键，避免旧目标的回执被误用于新目标。下一次来源成功刷新时重试，仍校验问题范围。
- 界面明确说明：待发及后续通知会发给保存的账号。搜索、保存、选择当前用户均不发送测试消息。

## 验证

- 相关单元测试 49 项通过；TypeScript 与 ESLint 通过。
- 新增覆盖姓名搜索、同名账号、接收人持久化、固定目标直接发送、授权提示、无回执拒绝、旧查询竞争及切换目标时的待发通知处理。
- 打包后的桌面回归 3 项全部通过（1.7 分钟），覆盖姓名搜索授权失败提示、同名账号区分和明确选择、保存不发测试消息、重启保留接收人、用户授权失效后仍直接投递给保存的账号；并回归双平台汇总与定时通知、账号映射。测试均为隔离数据和模拟 CLI。
- 候选账号单选控件按紧凑布局展示，已排除通用文本输入框的全宽样式，避免单选框与姓名分离。
- 搜索响应与命令以本机 CLI 1.0.48 的帮助及官方源码核对。没有自动升级 CLI，没有开启真实登录授权或发送真实飞书消息。
