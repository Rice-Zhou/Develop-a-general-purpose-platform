# 0.3.3 项目删除与问题刷新

## 项目生命周期

新增 deleteProject(projectId, expectedRevision)，贯穿严格 IPC、项目服务和唯一 SQLite。确认弹窗说明实际效果：项目从日常列表与任务视图移除，目录可以重新关联；保留本机历史分析记录、文档材料与固定快照，不删除代码目录、源文档、Git 引用或共享连接。

删除事务统一检查配置版本及活动任务状态，再写入同一项目 JSON 的 deletedAt、禁用标记及新版本，释放 repository_paths。排队、准备、运行、校验、取消中任务均阻止删除；UI 与后台共享活动状态常量。旧编辑和重试不能恢复已移除项目，新建项目使用新 ID，历史证据不会混到新项目。

删除是逻辑移除，没有第二份归档项目数据源。目前不提供恢复及彻底清理历史的界面；历史仍占用本机存储，保留的记录可以通过备份/后续管理能力处理。

数据库版本提升至 4，以阻止旧版忽略 deletedAt 而重新显示移除项目。v1/v2/v3 升级前均一致备份，失败不迁移；v3 仅提升持久化语义版本，不重建已有问题表。需要回退时须使用升级前备份及匹配版本，不能直接让旧版打开当前数据。

## BUG 刷新及原单链接

BUG 工作台在“范围内问题”提供“刷新问题单”，依次调用现有项目与负责人范围的读取适配器。没有扩大为全账户扫描。各范围分别显示未刷新、正在刷新、成功数量或失败缓存；只在全部范围成功且整体为空时给出无问题提示。

列表只存一份带当前范围标识的 workspace，刷新状态不另存问题数组；单号读取会替换对应批次并明确提示完整列表需要刷新。刷新失败不改为空列表，部分成功不会被包装成完整成功。切换项目、修改范围或卸载后忽略旧回包。

刷新 IPC 期限与后台单范围 5 分钟预算对齐，避免后台仍读取时前台 30 秒假超时。刷新后回读完整工作区，包含历史报告及其他范围缓存。

Jira 单号是可见链接。打开时 renderer 只传项目和快照 ID，主进程经私有服务通道从数据库取材料，复用 ScopePolicy 与 Jira 编号校验，再构造绑定实例的 /browse/ 链接交给系统浏览器；不能提交任意外部 URL。Trinity 批量列表及详情页 URL 契约仍未确认，明确提示，不伪造刷新或链接。
