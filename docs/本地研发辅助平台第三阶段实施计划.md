## 已授权范围与接入约束

用户要求继续开发第三阶段，补充 Jira 实例 `https://yfjira.mychery.com`，并明确使用 Jira CLI。通过本机 1.7.0 help 已确认 `issue list --raw --jql --paginate --project` 和 `issue view --raw`。平台不处理 Jira 登录密码，配置实际 exe 与 CLI 配置文件路径；只调用固定只读命令，结构化输出不支持则报错。实例和范围必须在返回值中复核。

Trinity 现有本地 API 资料确认 `GET /quality/bugRedux/getByBugId?bugId=…`，但项目分页查询契约未确认。先提供按编号读取并严格检查返回项目/负责人，明确不支持项目列表；不得调用全账户 assignToMe 再客户端过滤充当项目查询。真实接口字段若不符，返回契约错误。目标实例契约和真实模型分析未通过时，不宣称整个阶段完成。

## Global Constraints

- 不自动修改 BUG、评论或归属；不自动修代码、构建、提交或推送。
- 范围必须同时满足连接、实例、项目、BUG 类型和负责人；显示名不当作身份标识。返回越界即整批失败，不保存部分结果。
- 第三阶段提供手动刷新与预分析；定时监控仍为第四阶段。
- 任务进入已有串行队列，分析前重新读取问题并验证范围，Git 同步失败不得分析；开始外发前及结果提交前复查问题版本。
- 密钥使用已有主进程加密存储，Renderer 不得读回；Jira 认证交给 CLI；不自动读取既有 token 或浏览器 Cookie。
- 核心单测 60 秒、HTTP/CLI 单次 30 秒、模型任务 20 分钟；JSON 8 MiB，最多 100 页 / 5,000 问题；遇预算/不完整分页显式失败。
- schema 升级前一致备份；不覆盖旧需求报告，不创建第二队列或并行证据读取实现。
- 附件先保存元信息及未解析清单；不跟随描述中的 URL，不自动下载未确认域或执行附件。日志下载/更多 Trinity 字段需真实实例契约确认后扩展。

## Review Focus

1. CLI 配置指向另一实例、JQL 特殊字符、服务器忽略项目筛选时，材料不能进入错误项目。
2. BUG 在队列、Git 同步或模型运行中转出/改变，旧材料不能作为最新成功结果。
3. 分页重复、超量、部分失败，不能出现假空列表或半份更新。
4. 模型虚构证据/根因，必须拒绝；当前分支与问题版本差异及未解析材料必须保留。
5. v2 数据升级、报告事务失败、跨项目查询和连接删除后读历史，不能丢旧数据或串项目。
