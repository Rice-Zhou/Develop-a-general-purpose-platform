# 模型输出校验与取证错误恢复修复验收（0.9.2）

日期：2026-10-21。

## 失败证据和边界

只读查看本机失败任务 BUG20261020_14151 的事件：已经成功读取代码及日志，在第二轮的一批 readCode 请求中途触发一次输出修正，最终只记录通用 OUTPUT_INVALID。旧版没有保存最后一次具体校验原因或模型原文，不能追溯认定最终是某一具体字段或证据 ID 出错。没有改动真实任务、凭据、项目或问题单，也没有重发真实项目材料。

代码确认并通过失败测试复现：单个可恢复的取证错误直接跳出整批调用，剩余调用没有响应，也消耗了最终报告的一次修正机会；最终异常覆盖了具体校验原因。

## 修复行为

- 对明确可恢复的参数、路径、行范围、文本类型等取证错误，返回带错误码的对应 tool 响应；继续完成同批其他调用，让模型调整请求。失败不会生成证据，也不会被当作取证成功。
- 最终报告的结构和证据校验仍保留一次修正，总请求上限仍为 12 次。已取得证据和代码、日志校验不放宽。
- 修正事件和最终 OUTPUT_INVALID 显示具体校验原因；记录受限错误摘要，不记录模型原文。
- 取消、内容损坏、未知异常继续抛出，不作成功降级。提示明确代码和日志单次最多 400 行。

## 验证

- 两条新测试在修改前失败，分别复现整批取证中断和最终原因丢失。
- 17 项分析及订阅协议单测通过，覆盖错误响应对应关系、同批后续取证、跨项目路径拒绝、JSON/参数错误、最终独立修正及不可恢复异常原样传播。
- TypeScript 类型检查、受影响文件 lint、diff 检查通过。
- 最终打包 3 项桌面回归通过：BUG 队列和按钮状态、Codex 发现、当前代码和日志预分析。预分析回归在同批加入越界请求，再故意引用不存在的证据，验证模型收到错误且仍可修正输出，最终保存同时引用代码与日志的成功报告。
- 修正按钮回归的测试同步方式：预加载 API 由 Electron 冻结，赋值替换不能可靠阻塞 IPC；改为在点击事件微任务中直接检查提交状态。保留原断言，没有放宽产品状态要求。
- 发行 ZIP 83 个文件逐一 SHA-256 与便携目录一致。

本次未重新执行真实账号的目标 BUG 预分析。升级后可在任务历史重试失败任务；如模型仍输出无效内容，新版会显示实际校验原因，而不会仅显示通用错误。
