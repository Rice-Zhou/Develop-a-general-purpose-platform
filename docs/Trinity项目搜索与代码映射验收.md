# Trinity 项目搜索与代码映射（0.7.6）

## 目标与范围

用户已认可：支持搜索并选择 Trinity 项目关联代码项目；未匹配的问题可以直接关联；支持多对多；完成后重新打包。Trinity 车型项目名与本地模块项目名不同是正常情况，匹配只认实例地址和真实项目 ID，名称仅用于展示和搜索，不使用 AI 或名称相似度自动决定归属。

## 实现与使用

1. 项目管理 → 管理关联 → 读取 Trinity 项目，输入名称或 ID 后直接在输入框下选择。可添加多个项目，已关联项可逐项移除。原有只保存 ID 的映射仍保留，不会因本次列表未包含它而丢失。
2. 项目候选沿用当前账号问题列表及详情接口，提取、去重所属项目，不依赖已有代码项目，不新增未验证的项目列表接口。范围为当前账号负责的问题中的项目；没有问题的项目暂不列出。详情返回 projectName 时保留名称；缺失时明确显示“未返回项目名称”和实际 ID，不猜测名称。
3. BUG 工作台 Trinity 问题卡片提供“关联代码项目”。选择已有启用项目后保存，会重新读取问题，验证当前账号、问题范围和所属项目未变化，再追加实例地址及真实 ID 映射。保留既有映射、文档、代码配置与默认 AI 继承；使用目标项目版本防止并发覆盖。保存不会启动任务，也不调用模型。
4. 一份代码可对应多个 Trinity 项目，一个 Trinity 项目可对应多个代码项目。当前项目已映射时默认使用当前项目；只有一个匹配时自动选择；有多个匹配时在问题卡片“预分析代码项目”中选择，并将目标传给后台重新校验。未匹配、停用或已解除映射的目标无法通过接口绕过。
5. 预分析仍重新读取问题、更新所选代码项目并固定提交。读取后问题所属项目变化时停止，避免使用错误模块。Trinity 账号自动关联所有项目和飞书固定接收人行为保持原样。

映射仍以代码项目已有 trinityProjects 保存，名称为可选字段，不增加数据库表、独立映射来源或 schema 版本；数据库版本仍为 8。账号绑定构造共用同一函数。

## 验证

- 新增核心及存储测试，先观察缺失方法/目标列表导致失败，再实现。覆盖同名不同 ID、无代码项目时发现、账号中途变化、问题项目转移、明确选择目标、多对多、持久化、重复关联、跨实例拒绝、版本冲突及默认 AI 继承。
- 全量单测：52 文件通过，176 项通过；1 文件、5 项跳过，均为原有依赖 PLATFORM_TEST_JIRA_CLI 的可选本机 Jira CLI 验证。最终相关核心/存储/适配器测试单独复验。
- TypeScript、ESLint、diff 空白检查通过。多目标切换时，问题卡片显示的代码项目与所选目标同步；增加桌面断言验证显示与实际任务项目一致。
- 0.7.6 打包后的桌面回归 4 项通过：Trinity 命名搜索、直接关联、多对多目标选择、解除映射与问题归属变化拦截；Jira 刷新；飞书接收人持久化；独立资源关联及默认 AI 继承。桌面数据和平台均为隔离模拟，没有登录真实 Trinity、修改真实业务仓库、调用真实模型或发送真实消息。
- 新增桌面用例在旧 0.7.5 包上因缺少“读取 Trinity 项目”失败，证明新入口受到回归覆盖；新包复验通过。
