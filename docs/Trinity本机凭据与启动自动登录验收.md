# Trinity 本机凭据与启动自动登录验收（0.8.2）

日期：2026-10-21。开发目录：`D:/development/Develop-a-general-purpose-platform`。

## 使用与行为

在设置中创建或编辑 Trinity 连接时，可勾选“在本机保存账号密码，并在启动时自动登录”。默认关闭，既有连接保持关闭，不读取历史密码，也不从 token 推测密码。开启时需要输入密码并成功登录和验证身份，然后才保存设置。提交期间禁用此开关，避免许可状态在保存途中发生变化。

密码沿用 Electron safeStorage / Windows 系统加密，复用 FileCredentialStore，在密文中绑定连接 ID、实例地址、账号和 UID。数据库只保存开关与内部凭据引用，用户名仍作为已有连接元数据展示；密码不回填界面。公开连接投影统一移除 token 引用和密码引用。系统加密不可用时拒绝保存明文。

每个应用进程启动时最多自动登录一次，重新验证 Trinity UID；UID 不匹配不更新连接。成功后替换会话并清理旧 token，保留连接 ID 和项目关联。自动登录完成后启动问题轮询；后台服务单独重启会恢复轮询，不再执行账号密码登录。刷新界面、打开托盘窗口不触发额外登录。

失败在主界面显示错误码和重新登录入口，不循环重试，不保存响应正文或原始异常里的可能敏感内容。失败不冒充登录成功，不替换此前的会话；其他本地功能仍可使用。

关闭方式：编辑原连接，取消勾选并保存。账号和实例不变时密码可留空，保留已有会话而不再发起登录。删除连接、连接改为 Jira、或更换保存密码时，同样清理原密码。密码删除失败时保留原连接及引用，显示失败供重试；删除已不存在的文件按幂等清理处理，其他删除错误继续暴露。如果密码已清除而后续数据库提交失败，会返回失败；旧配置可能仍显示开启，下次启动明确提示凭据缺失，需要重新保存，平台不会恢复已删除的密码。

## 实现范围

- 主进程 `TrinityLogin` 复用原登录适配器、身份验证和凭据仓库，负责保存及一次性启动登录。
- 主进程启动门控让自动登录先于问题轮询；状态通过只读 IPC 提供给主界面。
- Trinity 配置界面增加开关、状态和关闭后清理提示。Jira 的登录方式保持原有行为。
- 连接仍统一存储于现有 issue-connections；密码由现有系统凭据仓库管理，没有独立账号配置库。

## 审查与边界

独立只读代码审查发现关闭后删除密码失败会失去原引用、Trinity 改为 Jira 时遗漏密码清理两项问题，均已修复并补充失败注入和打包桌面回归。没有新增自动登录循环或静默账号切换。

旧会话仍可能失效，自动登录仍依赖网络和企业认证服务。此功能不保证第三方账号永久在线；失败时请在设置重新登录。系统加密绑定本机用户环境，复制数据目录不能作为密码迁移方式。
