# 1.0.2 需求审核、资料库与连接设置验收

开发目录：D:/development/Develop-a-general-purpose-platform。版本：1.0.2。本次仅本地打包，未上传或发布 GitHub Release，已发布 1.0.1 保留。

## 已实现行为

- 主入口“AI 审核当前代码”复用有效 AI 和统一执行队列，读取当前工作区及未提交修改；需求上下文、提取与核对均不执行 Git 网络更新。项目管理手动更新代码保留。
- 疑似缺失/部分实现生成待确认需求；初始不预选。误报保存即隐藏；未完成先勾选确认，随后才提供完成选项。已完成重检缺失重开，同版误报保持关闭；AI 改判已实现不替用户完成。已处理可恢复，处理记录固定当时的报告与需求版本。
- 原文区域不再显示其他 BUG/日志或历史任务的默认错误；真实需求操作失败仍可见。项目切换隔离读取、入队和人工决定的晚返回。
- 资料库可无项目使用，支持多级分类、DOCX/PDF/飞书、通用 URL/路径/文本及用途和备注。普通引用不自动解析为需求。资源、分类、项目关联均为唯一存储；分类移动不改变内容版本。解除关联不删除资料，非空分类和被关联资源拒绝直接删除。
- 设置只显示保存连接；Jira、Trinity 和 AI 新增/编辑才展开，保存或取消收起并清空未保存凭据。原有 CLI 发现、Jira 多连接、Trinity 唯一账号、默认 AI 以及删除替代逻辑保留。

## 数据与实现取舍

- 使用用户指定目录及现有 develop/issue-milestone 分支，不额外创建 checkout；代价是没有第二份工作目录隔离。
- 资料迁移 schema11，人工状态 schema12，独立审查后追加决定依据迁移 schema13。旧版本升级前备份，未来版本拒绝读取；旧 schema12 的事件依据保留为空并明确提示，不把当前报告伪装成当时依据。
- B2/B3 修改相同 TaskService/Workbench，合并为同一实现提交；任务验证仍分别记录。
- 保留既有免密本地模型 API 支持，不新增统一密钥门槛；服务若要求认证，由真实请求明确返回错误。
- 已确认未完成仍允许用户纠正为误报；完成操作仍要求先确认未完成。
- 复用已有登录/连接表单并控制展示和异步生命周期，不新增第二套登录逻辑。
- 同批语义相同而 UUID 不同的需求只归并一条人工待办，MISSING/PARTIAL 优先；原始重复或矛盾结论保留于不可变报告，供人工查看。
