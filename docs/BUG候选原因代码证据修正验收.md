# BUG 候选原因代码证据修正验收（0.9.3）

日期：2026-10-21。

## 根因与范围

用户反馈的具体错误是候选原因没有引用本次取得的代码证据。提示词只强调 hypotheses 为待验证原因，没有明确每条 hypotheses 都需独立引用 code/worktree-code；后端却严格校验每条候选原因。原修正只说明通用规则，既未定位失败数组条目，也未汇总本次已经取得的证据类型及 ID。

本次统一提示与校验的要求，不将没有依据的猜测自动接受为报告。每条事实及候选原因都应引用与其相关的本次代码证据。其他条目的代码引用不能替代本条引用；若同一代码与多条结论相关，可以分别引用。日志或文档不能代替代码。

## 实现

- 将 BUG 分析目标放入 prompts.ts，明确 facts/hypotheses 各自的引用要求、允许 hypotheses 为空、没有代码依据的猜想应改为 missingInformation 中的补充材料或排查事项。
- 校验错误指出具体路径，例如 hypotheses[0].supportEvidenceIds/counterEvidenceIds，不输出候选原因原文。
- 修正消息提供结构化 instruction、error、availableEvidence（本次 ID 和类型），最多列出最近 200 条，明确 omittedEvidenceCount。模型仍需根据相关性选择证据或继续取证，平台不自动附加引用或删除候选原因。
- 总请求预算、一次最终修正、代码及日志证据真实性校验、完全没有依据时不保存成功报告，均沿用原规则。

## 验证

- 新回归在修改前失败；修改后验证：先取得代码与日志，再返回只有日志依据的候选原因，修正消息准确指出 hypotheses[0] 并给出实际代码 ID；模拟模型将该猜想改为待补充信息，保留有效事实和日志证据，成功生成报告。
- 分析及订阅协议 18 项单元测试通过。类型检查、受影响文件 lint 通过。
- 使用当前本地 Codex 账号、自动选择的最新 CLI、gpt-6.1-sol 和已保存的 AI 代理进行真实协议验证。仅发送合成登录函数和合成拒绝日志，未发送项目代码或真实问题材料。模型经过两轮请求读取代码与日志，返回的报告通过现有代码和日志证据校验；没有保存到真实任务或报告库。
- 该真实协议验证覆盖正常输出，候选原因的纠错路径由可控模型回归验证；没有重跑用户的真实目标 BUG。

最终完整发行包的 3 项桌面回归全部通过：BUG 独立日志与分析队列、仅引用日志的候选原因修正、需求原文提取与实现核对。发行 ZIP 的 83 个文件与便携目录的文件集合及逐文件 SHA-256 一致。git diff --check 通过。

初轮附加需求回归因重打包与测试交叉运行，测试正在使用的 ICU 资源被覆盖而失败。停止交叉运行后，重新完整打包并重跑；不修改产品来规避该错误。
