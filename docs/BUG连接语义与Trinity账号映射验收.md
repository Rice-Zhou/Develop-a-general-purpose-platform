# BUG 连接语义与 Trinity 账号映射验收

版本：0.7.0，Windows x64，2026-10-20。开发目录为 `D:\development\Develop-a-general-purpose-platform`。

## 使用与行为

Jira 允许保存多条连接，包括同一实例、同一账号下不同项目的连接。每条连接在设置中完成登录、搜索选择 Jira 项目和缺陷类型后保存，负责人由登录身份确认。保存时后台再次校验项目、身份和类型。代码项目只选择已有连接，不再重复读取和搜索 Jira 项目；通过切换连接动态更换对应 Jira 项目。当前每个代码项目仍只选一个 Jira 项目。

Trinity 只保留一个当前账号。网站根地址规范为 `/trinity` API 地址，LDAP 登录后再读取 `/sys/user/userinfo` 验证账号 UID。账号问题读取使用该 UID，不接受手填负责人替代登录身份。密码不保存，只加密保存会话 token；公开连接不返回凭据。

Trinity 保存成功显示“Trinity 已自动关联所有代码项目”，立即应用到已有代码项目，后续新建项目自动继承。重新登录复用当前连接 ID 并更新所有项目的有效账号；删除该连接解除全局账号。连接卡片不再提供 Trinity“关联项目”，项目编辑也不再提供“添加 Trinity 范围”、项目 Key、负责人或缺陷类型输入。

每个代码项目在“管理关联 → Trinity 项目 ID（逗号分隔）”维护明确映射。映射同时包含 Trinity 实例地址，使用精确项目 ID，不按项目名称猜测、不由 AI 决定是否匹配。BUG 工作台展示账号下所有问题和远端项目 ID；映射只控制能否预分析，不过滤账号列表。

- 当前代码项目匹配时使用当前项目。
- 当前项目不匹配、另有唯一匹配代码项目时，展示匹配项目并自动路由到该项目分析，使用该项目的 AI 和代码。
- 匹配多个代码项目时要求切换到其中一个匹配项目，避免任意选择。
- 没有匹配项目时禁用预分析并提示“当前问题与所有项目不匹配，无法进行预分析”。后台同样拒绝，不创建任务、不更新代码、不调用模型。

任务准备时重新读取问题，在 Git 更新前再次核对账号和项目映射；问题归属或配置在分析期间变化时，最终复查也会阻止报告成功保存。

## 读取、缓存与提醒

Trinity 使用目标前端已确认的 `POST /quality/bugRedux/getBugsByMultiProjects`，发送 `mode=assignToMe`、验证过的 `userId`、`allProjects=true` 和分页参数，不传代码项目过滤条件。先读取当前账号的 apiVersion/isGray，再读取每个 BUG 详情并校验 UID。账号列表和详情响应不符、分页不完整或重复、问题被转派均明确失败，保留上次材料并显示错误。

成功的账号列表通过现有问题仓库事务更新所有启用代码项目的账号材料，包含空列表；中途失败回滚全部项目更新。沿用现有快照和报告存储，不另建第二套问题来源。同一账号的并发相同查询共用一次读取，不同查询按账号串行执行，避免旧响应覆盖新列表；通知发送也按队列串行处理。Trinity 的轮询游标按账号维护，同一个新问题不会因自动关联多个代码项目而重复发送飞书提醒。提醒内容标明实际 Trinity 项目标识。

## 数据迁移

数据库 v8 升级前自动备份。旧 Jira 连接只有一个明确项目引用时迁入连接配置；存在多个不同引用时不猜选，设置中提示完善连接项目。旧 Trinity 范围迁为当前账号对应代码项目的明确映射，移除逐项目平台绑定；如存在多个旧账号，保留最近保存的一个为当前账号。升级前数据可从备份恢复。

旧 Trinity 连接没有已验证的 UID 时需重新输入账号密码登录，不能沿用旧手填负责人或猜测账号。需求资料库、默认 AI、项目 AI 覆盖和历史快照保留。连接或账号变化会更新受影响项目版本，过期编辑和任务继续沿用配置版本保护。
