# BUG 任务排队与独立日志下载及连接管理验收（0.9.0）

日期：2026-10-21；根目录：`D:/development/Develop-a-general-purpose-platform`。

## 交付行为

1. 不再因代码项目已有任务而禁用预分析。不同问题可连续进入现有串行分析队列；同一代码项目、来源和问题的活动分析去重。任务展示问题号、项目、类型和状态，支持取消运行中或排队中的单条任务。
2. 问题索引与手动/定时刷新共用自动日志入口，日志下载不要求 AI。复用现有日志服务的单条下载队列，每个下载有独立取消信号，以日志版本 ID 对应持久任务。AI 队列和下载队列互不占用执行器；AI 只等待并消费索引时下载的材料，不发起下载。取消 AI 不取消共享下载；下载取消/失败后预分析等待用户处理，可独立重试或明确选择仅按代码分析。附件发现失败有明确任务错误，未经确认的空列表不作为无日志。
3. 删除被项目引用的 AI 连接时，列出受影响项目并要求明确选择替代连接或解除关联。数据库事务同时更新默认 AI、全部项目引用（含已移除项目）及连接列表，失败整体回滚。解除关联持久化为明确未配置，未来创建新默认也不会改变该决定；项目编辑可显式恢复默认继承。真正依赖该 AI 的活动任务需先取消；日志下载和纯代码更新不阻止删除 AI。
4. Trinity 排除状态为 Closed 的问题，不区分大小写、忽略前后空格；统一用于列表、缓存展示、按编号读取和预分析归属检查。Jira 既有非完成状态过滤不变。
5. 终止任务可手动从历史列表移除，保留底层记录与事件，确保已有报告、代码、日志的引用可追溯。活动任务不能删除；已移除记录不能再次重试。恢复启动时的日志任务会明确标为中断，可通过独立重试重新下载。
6. Codex 实际执行前再次发现最新 CLI 并验证原模型，保留原连接 ID、代理、权限和项目关联，不修改保存配置、不降级、不自动换模型。实际执行器身份记录解析后的 exe。

## Codex 故障核对

本机非敏感配置检查发现：默认 AI 已是桌面端 CLI，但 E0V 空调单独覆盖仍关联旧 npm CLI，模型均为 gpt-6.1-sol。仅改变默认连接不能改变项目覆盖，这是旧 CLI 仍生效的路径；本次在实际调用前解析最新 CLI，避免旧保存路径继续执行。

使用本机桌面端 0.163.0-alpha.10.2、原账号、gpt-6.1-sol 及既有 HTTP 代理 127.0.0.1:7897，仅发送输出 1 的请求已成功。没有发送用户代码/日志，没有改动真实账号、项目或认证文件。

4 条宿主 SKILL.md YAML 错误在成功调用中仍会打印，因此不能单独认定其为进程退出根因。修复后的错误展示优先保留 stdout JSON 中 error/turn.failed 的实质错误，统一脱敏，不收集普通 agent 输出；stderr 仍作为诊断，不静默吞错。

Codex 参数增加 project_doc_max_bytes=0、skills.include_instructions=false、skills.bundled.enabled=false，关闭自动项目说明和技能说明注入。未修改用户个人 skills 或 config。宿主技能扫描日志仍可能存在，不能声称完全隔离所有技能加载；已确认无效的开发开关没有写入产品。官方说明：https://learn.chatgpt.com/docs/non-interactive-mode （ignore-rules 仅跳过 .rules）。

## 数据升级与验证边界

数据库版本升至 10。升级前自动备份 v9 数据库；旧版拒绝打开新数据，避免把日志任务误当作 AI 任务或恢复已移除历史。回退旧版本需使用升级前备份，不直接打开新版数据库。

独立审查发现并发刷新可能在等待旧下载取消后竞争同一日志 generation。已加入等待后的再次校验与纯内存复现测试，只允许最新请求发布；日志重试次数按 generation 记录。

针对性测试已覆盖队列去重、逐条取消、分析不发起下载、并发覆盖、软删除保留追溯、AI 删除事务与失败回滚、明确未配置、Closed 过滤、Codex 最新执行路径及真实错误脱敏。

首轮全量回归共 283 项：276 通过、2 项旧数据库版本断言失败、5 项原有跳过；两条断言从 v9 更新到 v10 后，与迁移及日志测试合计 22 项重跑通过。Git 任务和安全回归在本轮全量中通过，没有扩大无关测试超时。

最终增量回归通过 249 项单元测试，原有 5 项跳过；另有取消与关闭流程的 17 项针对性测试通过。类型检查、lint 通过。最终 0.9.0 打包产物的 10 项桌面端到端测试全部通过，覆盖自动日志下载、逐条取消、分析排队、历史删除、AI 删除与解除关联、Trinity 自动登录和 CLI 发现。

附件信息尚在读取时，预分析等待已有索引操作，不会发起第二次下载；取消分析仅取消等待，不中断共享日志索引。退出应用同时触发监控、任务及下载取消，待它们结束后再关闭数据库。Codex CLI 发现也接收任务取消信号，避免取消后仍等待探测完成。
