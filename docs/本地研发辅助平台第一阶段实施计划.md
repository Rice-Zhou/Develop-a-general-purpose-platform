# 本地研发辅助平台第一阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. 本计划推荐当前会话直接执行；执行方式以用户评审结果为准。

**Goal:** 交付一个可以在 Windows 运行的真实桌面应用，支持多项目配置、独立分析目录验证、安全更新配置分支、固定代码快照以及持久化任务记录。

**Architecture:** Electron 主进程管理窗口和系统能力，受限 preload 向 React 提供业务接口，utilityProcess 中运行应用用例和 SQLite。Git 作为适配器接入；领域协议不依赖 Electron，目录、项目和任务在单一数据模型中表达。

**Tech Stack:** Electron、React、TypeScript strict、Vite、Zod、SQLite 与 better-sqlite3、Vitest、Playwright、Electron Forge。

**Spec:** [本地研发辅助平台技术选型与架构设计](./本地研发辅助平台技术选型与架构设计.md)，重点实现第 3 至 7 节、第 11 至 14 节中属于本地基础的要求。

日期：2026 年 10 月 19 日。状态：用户已认可并由当前会话直接实施；第一阶段已交付。实际完成项、验证证据及边界见 [开发验收记录](./第一阶段开发验收记录.md)。下文保留原批准计划作为实施基线，实际文件拆分与发布方式以验收记录为准。

## 1 总体交付与阶段边界

最终目标仍是设计文档规定的完整第一版。本计划只详细拆解可以独立验收的第一阶段，不以桌面框架代替完整产品。后续按同样方式形成独立实施计划，持续沿用既定接口。

| 阶段 | 结果 | 进入该阶段的条件 |
| --- | --- | --- |
| 第一阶段，本计划 | 桌面项目配置、Git 同步、不可变代码快照与任务历史 | 实施计划评审通过 |
| 第二阶段 | DOCX、文本 PDF、飞书、检索、需求核对和一个模型 API | 第一阶段通过，取得可用模型及飞书接入配置 |

## 2 Global Constraints

- 每台开发电脑独立安装，无需中心服务器。每位开发者只配置自己参与的项目。
- 开发者自行下载代码，为每个项目配置独立分析目录、远程仓库及分支。平台不负责克隆仓库。
- 分析前自动更新对应分支；更新失败时停止该任务，不用旧代码冒充最新结果。
- 禁止自动 stash、reset、clean、checkout、rebase 或创建合并提交。
- SQLite 是配置、任务和报告元信息的唯一权威记录。
- 没有可验证的只读模式或可用隔离机制的工具不能用于自动任务。
- 常规后端单测单例设置 60 秒超时。
- 首版默认全局一个 AI 任务、每项目一个活动任务；第一阶段同步任务同样按项目串行。
- 不执行仓库构建脚本，不推送代码，不修改 BUG 平台，不读取任何现有登录凭据。
- 产品工程原交付位置为 `outputs/local-dev-platform/`，现已按用户要求迁移至 `D:\development\Develop-a-general-purpose-platform`，后续开发、测试与打包统一在新目录执行。实际应用资料存放在 Electron userData。

## 3 Review Focus

1. 中文、空格、目录联接和路径大小写：同一仓库不能绕过项目绑定或目录锁。任务 2、3 覆盖。
2. 本地分支领先远端：`--ff-only` 成功或提示无更新也不等于远端最新版本，必须拒绝本地独有提交。任务 3 覆盖。
3. 多仓库中后一个失败：已更新仓库不回退，任务失败且不发布部分快照。任务 4 覆盖。
4. 关闭窗口、强退和重启：监控边界可见，执行中任务不会伪装成功或重复写结果。任务 4、7 覆盖。
5. 后台进程和 UI 协议：错误、恶意路径及不合法 IPC 不应变成通用系统命令。任务 1、3、6 覆盖。

## 5 公共类型约定

所有 ID 由应用生成 UUID。配置创建与修改使用版本检查，更新时携带 expectedRevision。Schema 作为协议与类型的共同来源，避免手写两份字段。

| 类型 | 第一阶段必需字段 |
| --- | --- |
| Project | id、name、enabled、revision、repositories、documents、issueBindings、aiProfileId |
| RepositoryBinding | id、canonicalPath、remoteName、remoteUrlFingerprint、branch、role |
| ProjectDraft | 无内部 ID 的用户输入及连接引用；路径由后端规范化 |
| RepositoryInspection | bindingId、branch、head、trackingRef、worktreeState、blockingReasons |
| RepositorySnapshot | bindingId、commit、fetchedAt、fileManifestHash |
| ContextSnapshot | id、projectId、configRevision、repositories、documents、createdAt |
| Task | id、projectId、kind、status、attempt、createdAt、updatedAt、error、contextSnapshotId |
| TaskEvent | taskId、sequence、stage、message、timestamp |
| AppError | code、stage、message、retryable、requiredAction、diagnosticRef |

第一阶段 Task.kind 仅允许 `PREPARE_CONTEXT`，其成功表示代码与上下文准备成功，不表示需求或 BUG 已被分析。documents 和 issueBindings 可以保存配置及能力状态，但未实现的适配器不能被运行。
