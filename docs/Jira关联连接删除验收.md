# Jira 关联连接删除验收（0.7.1）

## 问题与规则

旧版对已被代码项目引用的 Jira 连接执行删除保护，导致用户必须逐个解除关联才能删除。现在在设置点击“删除平台连接”即可删除，自动解除所有启用及停用代码项目的对应关联。

仅移除该连接及其项目关联。其他 Jira 连接、全局 Trinity 账号、代码项目、代码目录、需求文档、AI 设置、历史问题快照和分析报告保留。历史问题不再作为已删除来源的当前列表展示，旧快照不能继续提交预分析。

## 实现

- IssueService 删除路径不再使用“连接正在使用”拦截；编辑已关联连接的平台、实例或账号仍保留原有保护。
- DataStore 在同一个 SQLite 事务中保存连接列表、清理项目关联并增加受影响项目版本。停用项目也会更新；失败时全部回滚，旧版本项目编辑不能写回已删除关联。
- 主进程仅在上述事务成功后移除连接的加密凭据；界面明确提示删除及解除关联的结果，清除被删除连接的编辑状态。
- 不修改数据库结构，无须升级 schema。

## 验证

- 针对性单元测试：9 个文件、19 项通过，覆盖连接生命周期、BUG 范围、监控、账号关联及项目资源。
- 新增真实 SQLite 场景：启用及停用项目关联移除、其他来源保留、需求及历史快照保留、旧版本写回拒绝、重新打开数据库后结果持久化。
- 注入项目 UPDATE 失败，验证连接列表及项目修改一起回滚。
- TypeScript 类型检查和 ESLint 通过。
- 打包桌面回归：3 项通过，覆盖旧失效引用修复／重新登录／关联后删除、Jira 与 Trinity 全局关联及项目映射、BUG 刷新与链接。
- 桌面删除测试关闭应用后再次打开真实数据库，确认代码目录配置及历史问题快照仍在。

测试使用独立临时数据库、本地模拟服务和测试 Git 仓库，未使用真实企业账户或发送真实飞书消息。未重新运行完整端到端套件。
