# BUG 来源失效关联修复（0.4.1）

## 问题与证据

工作台提示 `ISSUE_NOT_CONFIGURED`，本机项目仍保存一个已不存在的 Jira 连接 ID；设置里还有两个同一实例的 Jira CLI 连接。只读检查升级前 v4 备份也发现同一失效引用，因此不是 v5 数据迁移生成的问题。检查仅投影连接 ID、平台、实例地址和项目绑定元数据，未读取或输出凭据。

原实现删除连接不检查项目引用，设置页又只能新增、删除连接，不能保留 ID 重新登录。由此允许留下悬空引用；现有资料无法确定该历史连接究竟何时、由哪次操作消失。

## 修复

- 核心服务统一检查引用：有未删除项目使用连接时，禁止删除连接或将它更换为另一个平台、实例地址或账号。停用项目仍属于有效引用；删除项目或解除绑定后允许删除连接。失败明确返回 `ISSUE_CONNECTION_IN_USE` 和项目名称。
- 设置页增加“编辑 / 重新登录”，复用原连接 ID 保存名称、CLI 配置或更新登录凭据，密码不回显。沿用主进程原有凭据生命周期：保存失败清理新凭据，删除被拒绝时保留原凭据。
- BUG 工作台失效来源显示“重新关联来源”，直接打开项目编辑。Jira 连接下拉明确标记“原关联已失效”，选择有效连接后重新读取登录身份和项目列表，再选择项目并保存。继续经过原有后端范围校验，不自动选择替代账号或跨来源降级。
- 数据库保持 v5，不增加迁移；没有直接改写用户正在使用的配置或从备份恢复凭据。

## 使用与边界

从托盘退出旧版，再运行 `out/releases/0.4.1/本地研发辅助平台-win32-x64/LocalDevPlatform.exe`。在 BUG 工作台点击“重新关联来源”，自行选择应使用的 Jira 登录连接及 `E0VPHEV` 项目，保存后刷新问题单。两个现有候选连接不会被自动合并或替换。
