# 项目需求文档管理（0.4.2）

## 交付行为

进入“需求核对”，选择当前项目，点击“管理需求文档”。支持多选本地 Word（.docx）及 PDF、手动添加飞书文档链接、修改类型与必需属性、删除文档关联。点击“保存文档配置”生效，取消或关闭不保存。

删除只解除当前项目的关联，不删除本地文件、飞书原文、其他项目的关联、历史快照、需求版本或报告。保存后页面提示重新准备文档上下文；后续捕获及分析使用项目最新配置，旧上下文继续代表当时的固定材料。

## 实现边界

原项目编辑页已经有文档配置，但入口隐藏在详情中，保存整个项目还依赖 Jira 身份校验及代码目录可访问。新入口通过受限 `saveProjectDocuments` IPC 单独更新文档关联，复用 `ProjectService` 和原 SQLite 项目记录。它只接受项目 ID、文档列表和预期项目版本，不能修改 BUG 绑定、代码目录、AI 连接等字段，不读取网络或 Git。

IPC 与核心用例共用请求 schema，文档类型及数量限制复用到完整项目配置中。SQLite 原有版本检查阻止过期修改覆盖配置，成功保存递增项目版本；运行中任务仍沿用现有项目版本检查。停用项目也可以维护文档配置，已删除项目明确拒绝修改。

两个文档编辑入口复用 `DocumentBindingsEditor`，移除项目编辑页原有重复实现。数据仍保存于同一项目记录，历史文档仍由固定快照承载；数据库保持 v5，无新增迁移。
