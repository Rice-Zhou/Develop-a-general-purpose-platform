# 本地研发辅助平台

本地桌面研发工作台。每个项目关联开发者自行下载的独立分析目录，手动更新代码与 AI 分析分开：BUG 预分析读取当前工作区（含未提交修改），保存固定代码与日志版本和任务历史。

项目开发根目录：`D:\development\Develop-a-general-purpose-platform`。后续开发、测试和打包均在此目录进行。技术设计、实施计划与验收记录统一保存在 `docs/`。

当前开发版本为 0.8.1。支持项目新增与删除、本地 DOCX/文本 PDF、飞书 CLI、固定快照检索、需求核对，以及 Jira / Trinity 只读材料和 BUG 手动预分析。添加项目可通过 Jira CLI 或账号登录读取并单选 Jira 项目，自动识别负责人及读取类型名称。Jira 项目输入时直接展开匹配列表，选中后回填到同一输入框。BUG 工作台可汇总刷新当前项目配置的全部 BUG 来源，明确区分成功空列表和失败，并通过问题号打开原单。Jira 展示所有非完成状态的问题；预分析按钮禁用时显示原因，未配置 AI 时提供默认 AI 设置入口。应用运行或驻留托盘时默认每 5 分钟检查已配置项目的新问题，通过飞书 CLI 提醒已保存的接收账号。

Trinity 登录认证与身份校验修复见 [0.7.2 验收记录](docs/Trinity登录Token与身份校验修复验收.md)，空灰度配置修复及真实只读验证边界见 [0.7.3 验收记录](docs/Trinity空灰度路由兼容验收.md)。账号问题筛选和详情适配已通过真实只读联调，见 [0.7.4 验收记录](docs/Trinity账号问题真实联调验收.md)。

飞书接收人姓名搜索、固定账号发送及授权提示见 [0.7.5 验收记录](docs/飞书接收人选择与固定账号通知验收.md)。

资源关联与默认 AI 的数据迁移、使用入口和验收见 [0.6.0 验收记录](docs/资源独立配置与默认AI验收.md)。

模型 API、飞书 CLI 和订阅工具的真实账号联调尚未完成；发布记录分别说明实际桌面验证和本地协议测试，不能将其视为已验证所有供应商或订阅账号。

第三阶段交付与限制见 [开发验收记录](docs/第三阶段开发验收记录.md) 和 [发行清单](docs/第三阶段发行清单.md)，范围依据 [第三阶段实施计划](docs/本地研发辅助平台第三阶段实施计划.md)。分支配置与真实 Jira 实读见 [0.3.1 验收记录](docs/分支配置与Jira实读验收.md)，配置与网络行为见 [0.3.2 验收记录](docs/项目配置与网络隔离验收.md)，项目生命周期及刷新见 [0.3.3 验收记录](docs/项目删除与问题刷新验收.md)，Jira 项目选择见 [0.3.4 验收记录](docs/Jira自动项目选择验收.md)，搜索交互见 [0.3.5 验收记录](docs/Jira项目搜索交互验收.md)。Jira 状态与预分析提示见 [0.3.6 验收记录](docs/Jira状态索引与预分析提示验收.md)。多来源读取及新问题提醒见 [0.4.0 验收记录](docs/多来源BUG汇总与飞书提醒验收.md)。新版输出到 `out/releases/0.8.1/`；启动前请从托盘退出正在使用相同数据目录的旧版。

## 使用

当前支持 Windows x64。运行应用后：

1. 打开“项目管理”，添加参与的项目。
2. 配置独立代码分析目录、远端名称和分析分支。选择目录后自动只读检测当前分支，确认匹配后点击“使用当前分支”；不匹配可直接填写目标分支。也可点击“重新读取”，检测结果不会覆盖已填写的值。多个仓库可以关联到同一项目。
3. 保存配置不会切换工作树。手动更新及需求核对仍检查配置分支和 upstream；BUG 预分析直接捕获实际分支/HEAD 与未提交内容，也支持 detached HEAD，不执行 fetch/pull/rebase/checkout/stash。
4. 点击“更新代码”，只更新本地仓库；需求文档和固定上下文请到“需求核对”页准备。
5. 手动更新遇到本地修改或分支冲突时按提示处理。BUG 分析无需先更新代码；捕获或分析期间代码变化会拒绝保存旧结论。
6. 需求资料库和 Jira 项目连接可独立保存，之后通过“关联项目”关联已有代码项目；Trinity 唯一账号登录后自动关联已有及未来代码项目，项目“管理关联”可统一调整文档、BUG 范围和 AI，无需重新检查代码目录。首个 AI 连接自动成为默认，所有未覆盖的项目自动继承；可在设置切换默认，或为单个项目选择独立连接。BUG 预分析共用代码项目的 AI，不另设 BUG AI。
7. 不再负责的项目可点击“删除项目”，确认后从日常项目和任务列表移除，并释放目录绑定。保留本机历史分析数据，不删除代码、文档或共享平台连接。有排队或运行中任务时，先取消或等待结束；后台也会检查，不能通过旧确认框删除已更新的配置。

需求工作台使用方法：

1. 在“需求资料库”独立添加 Word、PDF 或飞书 Docx/Wiki 完整文档 URL，随后关联项目；也可从项目中选择资料库文档，设置本项目必需/可选。
2. 打开“需求核对”，选择项目并点击“准备文档上下文”，查看原文、解析提示和检索范围。
3. 无需配置模型即可从原文加入需求，补充验收条件并保存需求版本。
4. 需要 AI 时，在“设置”创建连接，首个连接自动作为默认供项目继承；仅在需要覆盖时到项目“管理关联”选择其他连接。
5. 点击“AI 提取需求”或“开始实现核对”。每次重新同步代码及文档，原文变化时要求重新确认需求来源。成功报告保留固定提交、原文锚点、执行连接快照与限制。

BUG 工作台使用方法：

删除 Jira 平台连接会自动解除所有启用或停用代码项目的对应关联，保留代码目录、需求资料、其他平台连接以及历史问题快照和报告；连接与关联在同一事务中更新。详见 [0.7.1 验收记录](docs/Jira关联连接删除验收.md)。

1. 在设置中配置 Jira 连接，可选择本地 CLI 或账号密码登录，点击“登录并读取 Jira 项目”。输入名称或 Key 后直接选择匹配项目和缺陷类型，再保存连接。每条连接固定对应一个 Jira 项目；允许保存多条同地址、不同项目的连接，不限制为全局唯一 Jira。
2. Jira 连接卡片“关联项目”只需选择代码项目，无需再次搜索 Jira 项目。项目“管理关联”中选择其他已保存 Jira 连接即可更换项目。每个代码项目仍只关联一个 Jira 项目。保存 Jira 连接时重新校验登录身份、可访问项目和类型；关联已有连接无需联网重新发现项目。
3. Trinity 填写实例地址、用户名和密码。登录返回的 token 原样作为 `X-Token` 发送，不额外添加认证前缀。账号验证失败会显示业务码，UID 缺失和协议字段异常分别提示，未通过验证不会保存连接。网站根地址会规范为 `/trinity` API 地址。登录后验证 `/sys/user/userinfo` 返回的账号 UID，只加密保存会话 token，不保存密码。Trinity 为当前唯一账号，重新登录会更新已有账号，自动关联所有已有及后续代码项目，并提示“Trinity 已自动关联所有代码项目”。不再配置平台范围、手填 assigneeId 或逐个关联项目。旧连接缺少已验证 UID 时必须重新登录，不猜测身份。
4. 在代码项目“管理关联”点击“读取 Trinity 项目”，按名称或 ID 搜索并选择，可以关联多个项目；同一 Trinity 项目也可关联多个代码项目。候选从当前账号负责的问题中提取，无问题项目暂不列出；接口未返回名称时明确显示项目 ID。工作台的问题卡片提供“关联代码项目”，保存前重新读取问题、验证账号和所属项目，保存不会启动分析。映射绑定实例地址与真实项目 ID，名称不同不影响匹配；已有 ID 映射继续保留。当前项目已关联时默认使用当前项目；唯一匹配时自动选择；多匹配时可在问题卡片的“预分析代码项目”中明确选择。未关联、已解除关联或停用的项目不能作为分析目标；后台同样校验。详见 [0.7.6 验收记录](docs/Trinity项目搜索与代码映射验收.md)。
5. BUG 工作台点击“刷新问题单”统一读取 Jira 配置范围和 Trinity 当前账号的问题。Trinity 使用验证过的账号 UID 在服务端精确筛选负责人，不按代码项目过滤列表；一次成功读取会原子更新所有启用项目的账号材料。定时提醒按账号去重。单个来源失败保留上次材料并显示错误，其余来源仍可查看；只有全部成功且为空才展示空列表提示。问题号打开原平台详情，按编号读取可补充对应问题，历史快照和报告保留。
6. 选择“基于当前代码预分析”：重新验证问题归属 → 等待问题日志下载并解析 → 固定当前工作区与日志版本 → 模型取证 → 复查问题、代码和日志版本 → 保存报告。包含未提交修改，不更新代码；材料变化会停止并要求重试。日志失败时可重试，或明确选择“仅按代码预分析”，报告会记录缺失日志。
7. 报告区分代码事实和原因假设，展示支持/反对证据、复现条件、下一步和缺失信息，可读取固定提交证据及导出 Markdown。空输出或无代码依据的原因不会成为成功报告；明确缺少材料时进入等待处理。仅静态预分析，没有自动修复或 BUG 写操作。

刷新后自动下载真实附件，支持 UTF-8/BOM UTF-16 文本、ZIP 和 GZIP；可查看日志、定位附件原件或重试。视频、未知编码及其他格式保留原件并记录解析限制。Jira CLI 1.7 不提供二进制附件下载，需使用已支持的账号密码连接或明确选择仅按代码分析；不提取 CLI 私有凭据。平台不抓取描述中的任意 URL。源码与故障版本可能不同，当前代码不能用来直接否定历史 BUG。

AI 执行配置：

| 类型 | 配置方式 | 调用边界 |
| --- | --- | --- |
| 模型 API | 服务地址（例如 `host/v1`）、模型名、密钥 | Chat Completions 协议；先无凭据探测 HTTPS，传输失败才尝试 HTTP，禁止跨域重定向 |
| ChatGPT 订阅 | 自动发现并选择最新本机 Codex CLI，读取已登录账号模型后下拉选择 | 非交互、只读沙箱、禁用本机工具与插件；只通过 stdin 接收平台取证材料 |
| CC 订阅 | 本机 Claude Code 的实际 exe，先在工具完成登录 | 禁用工具、MCP、hooks 与会话持久化；只通过 stdin 接收平台取证材料 |

选择 ChatGPT 订阅后，自动检测 PATH、npm 与 Codex 桌面端安装目录，以实际版本选择最新 CLI；显示路径、版本和账号模型。编辑已有连接会重新检测，保存时复核 CLI 与模型，保留连接 ID、默认连接与项目关联。代理修改后需重新检测；未登录、检测失败或模型不可用时明确提示，禁止保存，不静默降级。详见 [0.8.1 验收记录](docs/Codex自动发现与模型选择验收.md)。

AI 服务地址和 AI 专用代理地址均可省略协议；界面展示两个候选及实际选中协议，HTTP 显示“未加密”。探测不含密钥、代码或日志；模型请求只发送一次，业务错误和发送后断连不自动改用另一协议重发。编辑现有 AI 连接时，密钥留空保留原密钥、连接 ID 与关联关系。

飞书在设置中配置 `lark-cli.exe` 和访问身份，点击“保存并检查飞书 CLI”。完整文档通过 v2 XML 及原始块 ID 导出，连续两次确认内容稳定；局部导出、持续变化或权限失败不发布完整快照。不自动下载内嵌图片或任意链接。

连接检查的含义：API 检查发送无项目材料的小请求；CLI 检查确认必要参数存在。CLI 登录、账号额度和实际权限由真实分析调用验证，安装工具不等于已获账号能力。模型连接只有明确允许发送材料后才能用于项目任务；不会自动切换供应商或计费来源。

需求分析前同步只快进配置分支；BUG 预分析保持当前工作区。项目管理的“更新代码”还支持保留本地提交的 rebase，冲突时由用户选择处理方式。平台不自动克隆、切换分支、stash、reset 或清理文件。不会构建项目、执行仓库脚本、推送代码或修改 BUG 单。

为了避免检出执行外部过滤器，第一阶段拒绝 Git LFS、检出过滤器和子模块；需要分析的子仓库可以单独配置为项目的另一个仓库。全局与系统 attributes 不参与检出，仓库内过滤器会被明确报告。

快照会在分析仓库写入 `refs/local-dev-platform/snapshots/<commit>` 本地引用，防止 Git 垃圾回收导致历史代码依据丢失。这些引用不推送远端，不改变工作分支。不要手动删除被历史任务引用的对象；本阶段不自动清理这些引用。

关闭窗口后进入托盘，明确退出才停止后台服务。异常中断任务显示为“运行中断”；BUG 重试重新捕获当前工作区，需求任务重试重新同步代码。上下文准备成功只代表快照完成；AI 提取、实现核对和 BUG 预分析分别有独立任务与产物。

解析与检索范围：DOCX 不提供不可靠的 Word 页码，PDF 保留页码及文本坐标；图片、空白/扫描页、乱码和结构损失可见。当前无 OCR。日志关键字搜索目前覆盖前 150 个文本文件的前 100 行，搜索结果明确提示覆盖限制；AI 可通过 readLog 按范围读取完整日志。初始代码内容索引最多 150 个文件 / 4 MiB、每文件前 400 行，其余保留路径索引并可通过固定提交继续读取；报告记录覆盖限制，零命中不能证明缺失。中文短词使用有界扫描，较长关键词使用 trigram 索引。

宿主通过 Koffi 调用 Windows Job Object，在后台服务初始化前登记进程所有权。后台服务异常退出后，必须确认旧进程及其 Git 子进程退出才允许恢复；系统拒绝进程管理时显示错误并停止恢复。其他操作系统暂不提供发行包。

## 从源码运行

需要 Node 24 LTS、npm 11 及 Git。Windows 应用包运行时不需要 Node 或 Python，但代码同步仍需要 Git。

```powershell
npm ci
npm run dev
```

工程包含本地 npm 版本，用于避免宿主 npm 版本过旧影响 Forge。安装后也可使用：

```powershell
node node_modules/npm/bin/npm-cli.js run dev
```

应用的 BUG 平台、飞书及 Git 默认直连，不继承进程代理环境；Git 还按次禁用 HTTP 配置代理与 SSH ProxyCommand / ProxyJump，不修改用户配置文件。SSH 使用 OpenSSH，保留用户 SSH 主机和身份配置，不执行外部自定义 GIT_SSH / GIT_SSH_COMMAND。

需要代理的 AI 连接可单独填写 HTTP(S) 代理 URL，留空直连。代理仅进入该模型请求或订阅 CLI 子进程，不修改全局环境或全局网络 dispatcher；代理失败不自动改为直连。当前代理 URL 不接收账号密码。订阅工具若在自身配置中覆盖环境代理，以工具实际行为为准，平台不改写其登录配置。

源码安装依赖、Electron 下载属于开发工具链，可单独配置其代理；不要把代理凭据或公司证书写入源码，也不要禁用 TLS 校验。

## 验证与打包

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
npm run make
```

`build` 生成可运行的 Windows 应用目录，`make` 生成 ZIP 和安装程序，产物位于 `out/`。打包后的程序也可以通过设置 `PLATFORM_EXECUTABLE` 指向实际 exe 来运行相同 E2E 流程。

`PLATFORM_BUILD_DIR` 可指定独立构建输出目录，例如 `out/releases/0.2.0`，适用于旧版本仍在运行时生成新版。`ELECTRON_ZIP_DIR` 可指定已有、已校验的 Electron ZIP 缓存目录，文件名必须与锁定的 Electron 版本及平台一致。没有设置时沿用 Forge 的正常下载流程。

锁定的 better-sqlite3 13 与 Koffi 3 自带 Node-API 二进制；Forge 保留生产依赖并解包原生模块，不重新编译这两个模块。升级版本时必须重新运行打包后的 E2E。当前安装程序未配置代码签名。

测试使用临时目录和临时 Git 远端，不接触开发者真实项目。单测超时为 60 秒，桌面测试也有明确超时。Playwright 自动操作真实 Electron 窗口，不使用演示后端。

## 本地数据

开发模式和正式应用使用不同的 Electron userData 目录，可在设置页查看实际位置。数据库保存项目、任务、事件和快照元信息；代码内容依据固定提交从对应分析仓库读取。移动或删除分析仓库会影响历史代码读取。

设置中的“备份本地数据库”使用 SQLite 一致备份能力。升级 schema v1 前会先生成一致备份，备份失败不迁移。数据库备份包含项目、文档块、内容哈希、需求版本、任务和报告；不包含代码仓库、`content/` 原始内容快照或可移植登录凭据。完整保留历史原文证据时还需保存应用数据目录中的 `content/`。恢复到其他电脑时需要重新关联路径和登录。

高级用法：`PLATFORM_DATA_DIR` 可指定独立应用数据目录，适用于隔离测试或独立配置空间。不要将它设置为代码仓库或资料原文目录。

## 工程结构

| 目录 | 职责 |
| --- | --- |
| `apps/desktop` | Electron 宿主、受限 preload、后台服务与 React 界面 |
| `packages/contracts` | IPC schema、领域类型、结构化错误 |
| `packages/core` | 项目用例、代码访问策略、任务调度及接口 |
| `packages/adapters` | Git 检查、安全同步、固定提交读取、进程树取消 |
| `packages/storage` | SQLite、项目存储、内容快照与凭据存储边界 |
| `packages/testkit` | 临时仓库测试工具 |
| `tests/e2e` | 真实桌面流程验证 |

外部接入仍需提供 Jira 部署类型、Trinity 实例接口、飞书访问方式以及实际模型和本机 AI 工具配置；这些条件不会由模拟适配器代替。

## 新问题提醒

BUG 工作台的“定时查询与飞书提醒”可设置间隔（默认 5 分钟）、暂停查询或关闭通知。首次成功读取每个范围时建立基线，不把存量问题作为新问题通知；随后在相同项目和负责人范围内发现新增问题时提醒，消息包含项目、单号及详情链接。Jira 排除完成状态，其余状态均可展示及触发新问题提醒。

飞书通知复用设置中的 CLI 路径。在 BUG 工作台展开“定时查询与飞书提醒”，输入接收人姓名并点击“搜索接收人”，根据姓名、部门及账号 ID 选择并保存。搜索需要 CLI 用户授权；如失效，按提示在本机终端执行 `lark-cli auth login` 后重试。保存后，机器人直接向该账号发送通知，不再查询 CLI 当前用户；CLI 用户切换不改变已保存的接收人。也可点击“使用当前 CLI 用户”一次性选择本人。未保存接收人时，首次通知会沿用一次当前用户识别。搜索、保存及选择当前用户均不会发送测试消息。机器人仍需有效的应用授权和发消息权限。

基线和待发送记录保存在本机数据库，普通重复查询和重启不会重复通知；发送失败保留记录并显示错误，下次范围刷新成功时重试，同一接收人的重试使用同一 CLI 幂等键；更换接收人会为待发通知生成新键，避免被旧接收人的发送记录去重。短暂转出再转入等发生在两次查询之间的变化无法保证捕获；远端消息已送达、进程在保存回执前崩溃时，重试去重仍受飞书幂等键有效期约束。退出应用停止查询，托盘运行继续；休眠或断网期间不能实时提醒。提醒不会自动启动 AI 分析。

## 0.8.0 日志与当前代码预分析

刷新问题后自动准备平台附件，工作台分别展示问题读取与日志下载/解析状态，可重试、预览文本和定位已保存原件。确认无附件显示“平台确认无附件”；接口错误不会当作空日志。Jira 账号连接使用同一账号读取附件；当前安装的 Jira CLI 1.7.0 不提供附件下载命令，CLI 连接明确显示不支持，可改用账号连接或主动选择“仅按代码和问题描述分析”。Trinity 使用已登录账号读取 quality-bug-file 附件。

文本支持 UTF-8 与带 BOM 的 UTF-16；支持真实 Trinity `.txt.gz` 日志（Node 原生 GZIP，校验完整性并复用解压预算）；ZIP 按条目解析并验证大小、CRC、路径、重复项和链接。单附件最多 512 MiB，单问题下载及解压分别最多 2 GiB，同时最多下载 2 个问题，ZIP 最多 10000 项、嵌套 2 层。不支持的格式保留原件并说明缺口。AI 使用日志清单与按范围读取工具，证据绑定具体日志内容和工作区清单；准备失败会等待用户处理，跳过日志必须明确选择。

模型 API 与 AI 代理均可输入 host[:port][/path]，自动显示 HTTPS/HTTP 候选。执行前先做无密钥、无项目材料的协议探测，HTTPS 连接失败才尝试 HTTP；HTTP 会明确标注未加密。HTTP 状态码（包括 401/405/429）代表协议可达，认证、额度及模型错误不会触发协议重发。实际模型 POST 仅发送一次；订阅 CLI 只选择其代理协议，不修改订阅服务端点。设置可编辑原 AI 连接并保留未重填密钥、默认关系和项目引用。

数据库升级到 v9，升级前自动保存 v8 数据库备份。数据库备份不包含日志/工作区内容对象；完整保留历史分析需要同时保留用户数据目录中的 content 目录。当前不自动删除历史内容或旧发行包。

验证结果及真实联调边界见 [0.8.0 验收记录](docs/BUG日志与当前代码预分析及AI协议自适应验收.md)。
